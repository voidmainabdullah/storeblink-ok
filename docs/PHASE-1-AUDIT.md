# Phase 1 Audit - Editor Foundation and Scene Graph

Date: 2026-07-24

## Current Result

The live `/dashboard/store` route now uses `EngineProvider` and the editor kernel created by `createEditorKernel()`. The live editor scene is loaded into `scene.store` as a validated `SceneTree`, and editor mutations run through Scene Graph command paths.

## Data Model Mapping

| Required Field | Current Implementation |
|---|---|
| `SceneNode.id` | Stable IDs generated by `storeSceneAdapter` or `createSceneNode()` |
| `SceneNode.type` | Built-in node types: `section`, `container`, `text`, `button`, `shape`, `image`, `svg`, `video` |
| `SceneNode.name` | Human-readable layer names shown in the engine editor layers panel |
| `parentId` / `childIds` | Fully represented in `SceneTree` and validated at load/deserialize |
| `props` | Text, button label, media src/alt, renderer-specific payload |
| `style` | Fills, strokes, effects, opacity, corner radius |
| `layout` | Raw layout container; layout engine remains later-phase work |
| `transform` | Position, size, rotation, scale, skew, transform origin, z-index |
| `meta` | Lock, hidden, timestamps |
| `extensions` | Store-specific mapping metadata such as source section/custom block IDs |

## State Management

| Store | Status |
|---|---|
| `scene.store` | Active Scene Graph node tree for `/dashboard/store` |
| `project.store` | Present for project/page model |
| `preferences.store` | Present for editor preferences |
| Engine Store | Not created; kernel is provided by React context |
| Selection/History stores | Present from later phases and used by the migrated runtime |

## Reused Pieces

- `EngineKernel`, `EngineProvider`, `useEngineContext`
- `EngineEventBus`
- `SceneGraph` types and validation
- `sceneStoreCommandGraph` as the live command-backed scene graph adapter
- Command/history systems from later phases
- Existing auth/profile loading and Supabase persistence primitives

## Replaced For `/dashboard/store`

- Legacy `StoreBuilderEditor` iframe runtime is no longer the `/dashboard/store` route.
- Legacy `theme`/`data-style`/`postMessage` editing path is not the live dashboard store editor runtime.
- New route path: `MyStore -> EngineProvider(createEditorKernel) -> EngineEditor -> CanvasShell`.

## Compatibility Notes

- `src/pages/Store.tsx` remains for the public storefront route (`/store/:slug`) and backward-compatible customer-facing rendering.
- Saved engine scenes are stored under `theme.engine_scene` so existing profile/theme data remains readable.

## Risks

- Public storefront rendering still consumes legacy theme fields unless it is separately migrated to render `engine_scene`.
- The migrated `/dashboard/store` editor intentionally preserves only the dashboard editor route as Scene Graph source of truth; public store route migration is separate.
- Legacy editor files remain in the repo but are no longer the production dashboard store editor entry point.

## Verification Evidence

- `npx tsc --noEmit`: passed.
- Focused Scene Graph/adapter tests: passed.
- Full verification is recorded in the final migration report and command output.

## Implemented ✓

- Engine Kernel and React Engine Context are present.
- Engine Event Bus is present and exposes scene mutation events.
- Scene Graph types, node factory, validation, traversal, CRUD, clone, serialize, and deserialize paths are present.
- Node Lifecycle registry exists.
- Serialization and Validation Systems exist.
- Scene Graph-backed `/dashboard/store` runtime is wired through `EngineProvider -> EngineEditor -> CanvasShell`.

## Missing ✗

- None for Phase 1 scoped foundation after the current migration.

## Partially Implemented △

- Node Lifecycle hooks exist but are lightly used by current built-in elements.
- Dependency Graph and full Computation/Invalidation Systems remain later architecture work, not Phase 1 completion claims.

## Technical Debt

- Some legacy profile fields still exist in Supabase schema for compatibility.
- Full architecture index contains later systems that must not be treated as complete because Phase 1 created the foundation.

## Regression Risk

- Future UI components must keep business mutations behind Engine Context and command/scene graph paths.
- Direct scene store writes outside engine/system code would violate Phase 1 ownership.

## Next Actions

- Continue routing new editor features through `useEngine()`/Engine Context.
- Implement Dependency Graph and Computation/Invalidation as dedicated later systems when their phase requires them.
